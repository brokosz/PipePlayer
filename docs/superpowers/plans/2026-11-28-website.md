# PipePlayer Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-page public site for PipePlayer on GitHub Pages, with a playable hero, sample clips, and a download button.

**Architecture:** Static `site/` folder (index.html, style.css, main.js, assets) published by a Pages Actions workflow. Audio and screenshot are generated once from the real app and committed. A shell check script stands in for unit tests.

**Tech Stack:** HTML, CSS, vanilla JS, Google Fonts (Outfit), GitHub Actions (`actions/upload-pages-artifact`, `actions/deploy-pages`), ffmpeg for trimming.

**Spec:** `docs/superpowers/specs/2026-11-28-website-design.md`

## Global Constraints

- Colors: green `#134d42` → `#0b3530`, gold `#f4b21f`, navy `#262f45`, tartan green `#1f6b3e`.
- Font: Outfit — 200 headings, 300 body, 500 buttons.
- Every download link is `https://github.com/brokosz/PipePlayer/releases/latest`.
- "Free · macOS 13+" (Package.swift is `.macOS(.v13)`).
- Clips: AAC `.m4a`, ≤ 60 s each, fade out at the cut.
- Works at 375 px wide with no horizontal scroll; `prefers-reduced-motion` stops the rings.
- Workflow deploys `site/` only.
- Sample tunes (traditional, Brad said "you pick"): Atholl Highlanders (jig, also the hero clip), Mason's Apron (reel), Skye Boat Song (slow air). Files under `~/Filen/band/bagpipe tunes/BWW Tunes/{a,m,s}/`.

## Review Focus

1. Pressing a second play button while one plays — the first stops and its button resets.
2. A clip that fails to load — its button disables instead of spinning forever.
3. Phone width — hero stacks (play button above or below copy), no overflow.
4. Clip ends — button returns to play, rings stop.
5. Keyboard — play buttons are real `<button>`s with labels that switch Play/Pause.

### Task 2: The page

**Files:**
- Create: `site/check.sh`, `site/index.html`, `site/style.css`, `site/main.js`

- [ ] **Step 1: Write `site/check.sh`** (bash, exits non-zero on first failure) asserting:
  - `index.html`, `style.css`, `main.js` exist.
  - Every `src=`/`href=` that is a relative path in `index.html` resolves to a file under `site/`.
  - Every `github.com/brokosz/PipePlayer/releases` link ends in `/releases/latest`; at least two exist (hero and install).
  - `style.css` contains `prefers-reduced-motion` and `Outfit`.
  - `index.html` contains `macOS 13+` and each of `.bww .bmw .abc .musicxml .mxl`.
  - Each `data-audio="…"` in `index.html` names an existing file.
- [ ] **Step 2:** Run `bash site/check.sh`. Expected: FAIL (files missing).
- [ ] **Step 3: Write the page** per the spec's "Page, top to bottom", with the hero exactly as mocked (option C, Outfit). Play buttons: `<button class="play" data-audio="audio/x.m4a" aria-label="Play Atholl Highlanders">`. `main.js`: one shared `Audio` element; clicking a button plays its clip and sets `.playing` on it (pause icon, rings run); clicking again pauses; starting another stops the first; `ended` and `error` reset the button, `error` also sets `disabled`. Rings animate only on `.playing`, and the hero button idles with a slow pulse. Copy from README for formats, features, and install. Include `<meta name="viewport">`, `og:` title/description/image (icon), favicon.
- [ ] **Step 4:** Run `bash site/check.sh`. Expected: PASS.
- [ ] **Step 5:** Visual check: `python3 -m http.server -d site 8123` and open in Chrome at desktop width and at 375 px; check all five Review Focus items by hand.
- [ ] **Step 6:** Commit `site/` — "Website: one-page site".
