# Set Lists Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `.pipeset` file of tunes that plays straight through in a tab, each tune once at its own tempo, joins seamless, with an editable list in the window.

**Architecture:** `PlaybackEngine` generalises from one tune to an ordered list of segments (a tune's voices + its tempo); events and the part timeline are built per segment and offset end to end, so the existing scheduler plays a set as one gap-free run. A single tune is a one-segment set. A `SetList` model owns the file; `AppState` gains a set mode that loads segments from it; `ContentView` shows the list only in a set tab.

**Tech Stack:** Swift 6 / SwiftUI, Swift Testing, Foundation JSON.

**Spec:** `docs/superpowers/specs/2026-11-27-set-lists-design.md`

## Global Constraints

- macOS 13 target; must compile under CI's Xcode 16 Swift as well as local Swift 6.4 — keep pure logic off SwiftUI views (they're main-actor there).
- Each tune plays once; no gap between tunes.
- File extension `pipeset`, UTI `com.brokosz.pipeplayer.pipeset`, conforms to `public.json`.
- File → New Set is ⇧⌘N; ⌘S saves an untitled set.
- The list (with + / −) appears only in a set tab. Add Harmony and the voice mute row are off in a set tab.
- Single-tune behaviour must not change; the existing suite must stay green at every task.
- Commit straight to `main`; push and check CI at the end.

## Review Focus

1. Changing tempo on tune 2 mid-play — playhead stays at the same spot in tune 2, tune 1's timing untouched, the tempo saved to the file.
2. Playing across a join — the tempo field switches to the new tune's tempo.
3. A set file moved to another folder together with its tunes — still opens (relative paths first).
4. Removing the playing tune, or the last tune — no crash; an empty set shows the list with + and no transport.
5. A join where the next tune starts with a pickup or a different metre — no gap: the next tune's first note-on is exactly at the previous tune's last note-off.

### Task 2: Engine plays segments

**Files:** Modify `Sources/PipePlayer/Audio/PlaybackEngine.swift`, `Sources/PipePlayer/Music/PlayOrder.swift`; Test `Tests/PipePlayerTests/PlaybackEngineTests.swift`, `Tests/PipePlayerTests/PartStructureTests.swift`

**Interfaces — Produces:**
- `struct PlaybackSegment: Equatable { var voices: [Voice]; var tempo: Double; var displayTempoScaleFactor: Double }` (in `PlaybackEngine.swift`).
- `func load(segments: [PlaybackSegment])`; `load(voices:)` becomes `load(segments: [one segment from the voices])`.
- `@Published private(set) var segments: [PlaybackSegment]`; `private(set) var segmentStarts: [TimeInterval]`; `var currentSegmentIndex: Int` (segment containing `currentTime`, last one past the end).
- `var tempo: Double` — now computed over `segments[currentSegmentIndex].tempo`; the setter calls `objectWillChange.send()`, rescales only the position inside the current segment (`start + (currentTime − start) × old/new`), rebuilds, and calls `onSegmentTempoChange?(index, newTempo)`. `displayTempo` uses the current segment's factor.
- `var onSegmentTempoChange: ((Int, Double) -> Void)?`
- `var partTimeline: [PlayOrder.PartTiming]` (now internal, not private) — each segment's melody tune, `PerformanceStyle.apply` + `EmbellishmentExpander.expand`ed (exactly what `MIDIEventBuilder` plays), timed at the segment's tempo and offset by its start. Segment *k+1* starts at segment *k*'s last `PartTiming.end`.
- `PlayOrder.PartTiming` gains `tuneIndex: Int` (default 0) and `func offset(by: TimeInterval, tuneIndex: Int) -> PartTiming`.
- `loopedPartIndex` is now an index into `partTimeline` (identical to `partIndex` for one tune).
- `voices` = the voices of a single segment; `[]` when `segments.count > 1`.
- Events: each segment's voices built at its tempo, channels per voice within the segment, times offset by the segment start; `duration` = last segment's end.

- [ ] Tests (two 1-part tunes, 4 one-beat notes each; tune A at 60, tune B at 120):
  - `segmentsPlayBackToBack` — `segmentStarts == [0, 4]`, `duration == 6`.
  - `theJoinHasNoGap` — A's last note-off time == B's first note-on time == 4.
  - `tempoFollowsThePlayhead` — seek 1 → `tempo == 60`; seek 5 → `tempo == 120`.
  - `changingTempoOnlyMovesTheCurrentTune` — seek 5, set tempo 60 → `segmentStarts == [0, 4]`, `currentTime == 6`, `duration == 8`, callback got `(1, 60)`.
  - `partLoopWorksInTheSecondTune` — seek 5, cycle to part mode → `loopRange == 4..<6`.
  - `singleTuneTimelineMatchesPlayOrder` — `load(voices:)` → `partTimeline == PlayOrder.timeline(of: expanded, tempo:)`.
  - PartStructureTests `offsetShiftsEveryPass`.
- [ ] Run → fails. Implement. Run full suite → passes (existing engine tests unchanged). Commit "Engine plays a list of tunes back to back".

### Task 4: Set mode in AppState

**Files:** Modify `Sources/PipePlayer/AppState.swift`, `Sources/PipePlayer/TuneOpener.swift`; Test `Tests/PipePlayerTests/AppStateTests.swift`

**Interfaces — Consumes:** Tasks 1, 2. **Produces:**
- `@Published private(set) var setList: SetList?`; `var isSet: Bool`; `@Published private(set) var entryProblems: [UUID: String]` (missing file / parse error text).
- `func newSet()` — empty untitled set named "Untitled Set", `currentURL = nil`.
- `open(url:)` dispatches `.pipeset` to set loading (`currentURL` = the set file, added to recents like a tune).
- `func addToSet(urls: [URL])`, `func removeFromSet(id: UUID)`, `func moveSetEntries(from: IndexSet, to: Int)`, `func saveSet(to url: URL) throws` (rebases, writes, sets `currentURL`, name = file name without extension).
- `func entryIndex(atSegment: Int) -> Int` / segment ↔ entry mapping (problem entries are skipped).
- Every edit reloads the engine's segments, keeps playback position when the playing tune survives the edit (else stops at 0), and writes the file when `currentURL` is set. `onSegmentTempoChange` stores the tempo on that entry and writes.
- `addHarmony` is a no-op in a set (when the harmony plan has landed).
- `TuneOpener` treats a `.pipeset` like a tune (same tab routing); `chooseTuneFiles()` allows `pipeset`; a separate `chooseSetTuneFiles()` excludes it.
